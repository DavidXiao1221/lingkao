# 临考小规模试用包

用于 **v0.2-alpha.3** 的第一轮当面试用。先邀请 3–5 位正在学习或刚学过高数的学生，一次一位，在主持人的电脑上体验。本轮要发现操作、讲解和学习报告中的问题；不以几道题的正确率证明提分或教学效果。

**从这里开始：** 启动独立试用环境 → 给学生阅读 [学生说明](student-guide.md) → 用 [观察表](observation-template.csv) 记录 → 完成后按 [反馈问题](feedback.md) 访谈 → 用 [汇总模板](summary-template.md) 排定修复顺序。

## 第一位学生到来前

1. 固定本轮为 v0.2-alpha.3，记下实际 Git 提交号或所用压缩包名。3–5 人之间不临时修改题目、文案或判题逻辑；必须修复的问题先结束本批，修复后另开批次。
2. 先按 [运行说明](../app/README.md) 安装依赖并运行测试。首次安装需要网络，依赖齐备后学习流程可离线运行。用主持人的演练记录走通流程，不将其计为学生数据。
3. 为试用使用独立数据库和一个专用浏览器配置文件。不要在平时开发的页面中直接清除现有学习记录。只打开一个学习标签页，准备纸笔、时钟和记录表。**同一浏览器配置中的 Cookie 不按端口隔离：仅换端口不够，必须使用专用配置。多个无痕窗口也不能当作不同配置。**
4. Windows 双击本目录的 [start-trial.bat](start-trial.bat)，或在仓库根目录的 PowerShell 执行下面的命令。它固定使用 `output/pilot-runs/batch-01/learning.sqlite3` 和 8010 端口；让终端窗口保持打开。macOS / Linux 使用 `bash pilot/start-trial.sh`。

```powershell
.\pilot\start-trial.bat
```

5. 在专用浏览器中打开 **http://127.0.0.1:8010/**，确认是开始页。可另开 `http://127.0.0.1:8010/api/health` 核对 `version` 为 `0.2-alpha.3`，然后关掉该标签页。地址只在这台电脑上可用。
6. 在本批目录中复制一份观察表与汇总模板。每人再建 `P01`、`P02` 等目录。真实观察、导出和截图都只放到 `output/pilot-runs/`；本目录中的模板保持空白。
7. 记录操作系统、浏览器、屏幕宽度、所用版本及主持人演练已完成。学生使用与主持人演练不同的匿名身份：演练结束先导出需要保留的资料，再点击“清除／下一位测试者”，阅读确认框并确认，核对回到开始页。

恢复同一批试用时重新运行启动器，并使用原浏览器配置和相同地址。若 8010 已被占用，先检查是否已经启动本批服务，不要重复启动或随意清除记录。需要开新批次时先结束、归档当前批次，再单独配置新数据库路径和批次目录。

## 邀请文案模板

下面的文字供你自行发送，本试用包不会联系任何学生。

> 我在做一个换元积分练习工具“临考”，想邀请你当面体验一次。适合正在学或刚学过高数的同学，预计预留 30–45 分钟，包括体验和反馈。这不是考试，也不需要提前复习。我主要想观察哪里不好用、哪里讲不清楚；不会做题或不会操作也能提供有用的反馈，不需要为了反馈而做对。试用在我的电脑上进行，不需要注册。会用匿名编号记录操作和反馈，你可以随时停止，也可以提出不保留本次资料。如果愿意参加，我们再约方便的时间。

不要提前发送题目、答案、解题演示或预设讲解。已经看过本单元题目或参加过演练的人可以帮助检查操作，但标为“已接触题目”，不能混入首次体验的独立作答证据。

## 每位学生的操作清单

### 1. 开场，约 3 分钟

- 分配 `P01` 等编号，只记录学习背景的大类：正在学高数／近期学过／其他，以及是否见过本版题目。不要收集姓名、学号、手机号或具体班级。
- 请对方阅读学生说明，口头确认愿意参加并允许记录匿名操作与反馈。默认不录音、不录像；如要截图，先说明只截应用界面。
- 主持人说：“你按平时习惯操作即可。卡住或不想继续时直接告诉我；不是在考察你。我会先观察，再记录需要帮助的位置。”
- 开始前可以确认鼠标、键盘和页面能使用；不讲换元方法、不演示题目答案、不要求使用某个提示。

### 2. 独立体验，约 20–30 分钟

让学生填写自己的时间预算，按页面走完：**1 道诊断 → 必要知识和示范 → 2 道引导练习 → 2 道独立变式 → 2 道新题复测 → 报告**。基础补练是可选项，不要求人人完成。时间预算不是倒计时，不强制学生赶在预算内做完；记录实际用时。

主持人观察学生是否知道下一步、表达式是否能输入、帮助是否解决具体疑问，以及报告是否能被理解。学生可以自然说出想法，但不要要求在每道题推导时持续口述，以免额外增加负担。

**介入约定：** 学生主动求助、明确无法继续，或同一操作反复失败时，先记下页面、输入现象和原话，再提供最少的操作指引。不要解释数学方法或替他输入答案。若确实提供了数学帮助，逐字记录涉及的题目；系统不能记录主持人的口头帮助，该题不能在人工总结中视为独立完成。

可以中性地说：“你现在想做什么？”“你原本期待这里发生什么？”避免问“这个按钮是不是不明显？”或“讲解是不是很清楚？”。训练中是否看提示由学生决定；不要为了试功能引导他查看答案。

### 3. 报告与访谈，约 5–10 分钟

先请学生用自己的话解释报告和下一步打算，再使用反馈问题。不要先替学生解释报告标签，否则无法观察原始理解。记录回答后，可以澄清误解，并标明澄清发生在访谈之后。

完成标准是到达报告并完成反馈；跳过题目也可走完流程。完成流程不等于学会。没有到达报告则记为“中断”，保留原因、最后环节和实际用时，不补填“完成”。

### 4. 导出、核对，再换下一位

1. 点击“导出学习记录”，把下载的 JSON 放到该学生的本地目录，另存为 `P01-learning.json` 等。原文件名中的随机编号是应用匿名身份，不必改动 JSON 内部字段。
2. 打开 JSON 确认能读取，核对 `app_version`、`participant`、`phase`、`post_done` 及 `attempts` 与本次体验大致一致。核对重点包括是否使用帮助、是否重试或跳过；格式错误和仅输入的草稿不属于作答记录，不会出现在导出中。
3. 在本地汇总表登记 `P01` 与导出文件的对应关系。保留中断、主持介入、学生原话等观察资料，因为它们不会由程序自动导出。
4. **确认导出已保存且能打开后**，点击“清除／下一位测试者”，阅读不可恢复的提示并确认。此操作删除当前浏览器对应的学习记录。核对已回到开始页，下一位没有上一位的答案与进度。
5. 不要用“再练一次”替代清除：重练会保留旧的作答与辅助证据，也不会重新开放未见题复测。

### 学生中断时

- 学生希望停止时立即停止，不要求为完成流程补答或跳过。
- 训练或安排阶段允许导出时，先导出已有记录，再根据是否需要继续决定保留或清除。
- **诊断、复测期间不能导出。** 不要为拿到导出而替学生作答、强迫继续或代点跳过；保留当前浏览器配置和数据，登记“测评中断／暂未导出”。下一位改用另一个独立浏览器配置，不能沿用此人的身份。
- 批次结束后如需保留未导出的进度，先停止该试用服务，再备份本批数据库及存在的 SQLite 辅助文件。数据库备份不能代替观察记录，也不应公开上传。
- 学生要求不保留资料时，清除对应学习记录和本地参与者资料；若已留有含该记录的整库备份，也一并处理。不得以“还不能导出”为由保留对方要求删除的数据。

## 观察表填写规则

[observation-template.csv](observation-template.csv) 使用 UTF-8 BOM，可直接用 Excel 打开。首行是固定表头，其后为空白待填；一行记录一件事件。复制后填写，不在公开模板中录入结果。

- **时间或相对分钟：** 统一使用开始后的 `mm:ss`，或完整时间；同一批不混用。不要只写“很久”。记录开始、各主要阶段进入、结束／中断时间，便于计算实际耗时。
- **环节：** 开始／诊断／示范／引导练习／独立变式／基础补练／复测／报告／访谈。题目名称使用页面上能识别的阶段与顺序，不填写内部编号。
- **事件类型：** 阶段开始／阶段结束／输入困难／导航困难／求助／报错／理解疑问／正向观察／中断。未发生的事件不必补写。
- **观察事实：** 记录看见的动作、出现的提示和次数；推测另填“待核对事项”。逐字原话与主持人的解释分开。
- **主持人介入类型：** 无／操作指引／数学帮助／其他。写清介入原话和后续操作，不能只写“协助”。
- **证据文件与位置：** 填本地导出／截图文件名、题目名称及逐次记录序号。没有证据填“未留存”；不要填写 Cookie、CSRF 或其他凭证。
- **暂定问题级别：** 使用下方分级。疑似错误先写“待核对”，核实之后再分级。

建议文件布局（这里只说明命名，不代表已有试用结果）：

```text
output/pilot-runs/<批次>/
  batch-summary.md
  learning.sqlite3
  P01/
    observation.csv
    feedback.md
    P01-learning.json
  P02/
    ...
```

`output/` 已被 Git 忽略。不要为了分享而把学生记录移到 `pilot/` 或发布附件中。整库备份含学习状态与会话信息，仅用于本地恢复；对外反馈问题时整理最少的、去除身份信息的复现步骤。

## 停止条件与汇总顺序

| 级别 | 判定依据 | 处理 |
|---|---|---|
| P0 | 核实出现记录丢失、不同学生记录混入、可复现的数学误判或异常答案泄露 | 暂停后续试用，保留最少复现证据，先修复和回归；受影响结果不能用于学习判断 |
| P1 | 核心流程卡住、无法输入所需表达式、关键文案导致错误理解，必须主持人介入才能继续 | 优先修复后再扩展试用；标明可行的临时操作方法 |
| P2 | 可以继续，但有阅读、布局、提示顺序等体验问题 | 结合影响人数和修复成本排序 |

程序明确显示“待核对”本身不是已经误判；先保存原表达式与题目，另行人工核对。怀疑判题错误时先暂停该题的判断，不让学生不断修改成程序喜欢的答案。

按 [汇总模板](summary-template.md) 先逐人记录是否完成、时间、介入和中断，再合并同一问题。写“3 位中 2 位找不到下一步”等原始人数，注明样本范围；不要换算掌握率、提分百分比或通过概率。诊断与复测题目未做难度等值标定，正确题数只能分别呈现。

优先处理 P0，再处理阻断最多的 P1；P2 看影响和频次。3–5 人足以提供下一步修复线索，不足以代表国内大学生整体，也不能单凭主观满意度决定学习效果。没有观察到问题也不等于已证明产品可靠。
